## User Story

> **As a** RAG pipeline developer,  
> **I want** all document ingestion to flow through a single LlamaIndex IngestionPipeline path,  
> **so that** I eliminate code duplication, ensure consistent chunking/embedding, and can reason about data flow with one mental model.

---

## Problem Statement

The codebase has **two parallel ingestion paths**:

1. **LlamaIndex IngestionPipeline** (`src/core/pipeline/ingestion.py`) — used for `sigma_docs`, `sigma_spec` collections
2. **Direct Qdrant client** (`src/infrastructure/vectorstore/__init__.py:149-168`, `src/application/documents/indexing.py:78-83`) — creates `TextNode` manually, generates embeddings separately via `embed_documents()`, stores directly in Qdrant

This causes:
- **Duplication**: Embeddings generated twice for same data in some flows
- **Inconsistency**: Node parsers (`MarkdownNodeParser` vs manual chunking) applied differently
- **Unclear ownership**: No single source of truth for "how does a document get embedded"
- **Cache bypass**: Direct Qdrant writes skip `IngestionPipeline` caching entirely

### Current Flow (Before)

```
SigmaRule → SigmaChunker → Document[] 
    → indexing.py:_generate_embeddings() → embed_documents() 
        → factory.py:get_embedding_model().get_text_embedding_batch()
            → [list of floats]
    → QdrantService.add_vectors(embeddings, documents, metadata)
        → QdrantVectorStore.add(nodes)  ← bypasses IngestionPipeline cache
```

### Target Flow (After)

```
SigmaRule → SigmaChunker → Document[] 
    → indexing.py:ingestion_pipeline.run(documents)
        → IngestionPipeline built with [node_parser, splitter, embed_model]
            → embed_documents() still used for standalone embedding needs
                → factory.py:get_embedding_model() (singleton ensured)
```

### Architecture Decisions

1. **Keep `embed_documents()` in factory.py** — needed for standalone use cases (e.g., user query embedding before search). But ensure it uses the same singleton.
2. **Replace `QdrantService.add_vectors()` usage in indexing.py** with pipeline-based ingestion. The direct method stays available as internal utility but is no longer the primary path.
3. **Preserve existing TextNode metadata fields** — `rule_id`, `chunk_type`, `source_file` must all survive the pipeline transformation.
4. **Migration strategy: delete + full reindex** — no incremental migration script. Before inserting new vectors via pipeline, clear the target collection entirely (or delete by rule_id prefix), then insert fresh. This avoids duplicates and simplifies Phase 1 significantly. Phase 2 `ref_doc_id` tracking is nice-to-have but not required for this story.

### LlamaIndex Patterns to Use

From docs (`/python/framework/module_guides/loading/ingestion_pipeline/`):

```python
# CORRECT: Pipeline with vector store attached
pipeline = IngestionPipeline(
    transformations=[
        SentenceSplitter(chunk_size=512, chunk_overlap=50),
        embed_model,  # HuggingFaceEmbedding instance
    ],
    vector_store=qdrant_vector_store,  # QdrantVectorStore instance
)
nodes = pipeline.run(documents=documents)
```

The `vector_store` parameter auto-inserts nodes into Qdrant after embedding — no manual add needed.

### 1. Modify `src/application/documents/indexing.py`

**Remove:**
- `_generate_embeddings()` function (lines 168-175) — dead code if chat path uses `embed_documents()` from factory.py directly; verify before deleting
- Direct call to `service.add_vectors()` in `index_sigma_rules()` (lines 77-83)

**Add:**
```python
import asyncio
from src.core.pipeline.ingestion import IngestionPipelineBuilder, get_embedding_dimension

# Module-level lock registry — prevents concurrent writes to same collection
_collection_locks: dict[str, asyncio.Lock] = {}


def _get_collection_lock(collection_name: str) -> asyncio.Lock:
    """Get or create an asyncio lock per collection."""
    if collection_name not in _collection_locks:
        _collection_locks.setdefault(collection_name, asyncio.Lock())
    return _collection_locks[collection_name]


async def index_sigma_rules(...) -> dict[str, Any]:
    ...
    lock = _get_collection_lock(collection)
    async with lock:
        # Delete + reindex strategy: clear old vectors before pipeline insert
        await service.delete_all_vectors_in_collection()  # or Qdrant client equivalent
        
        builder = IngestionPipelineBuilder(collection_name=collection)
        pipeline = builder.build(skip_splitter=True)  # chunks already created by chunker
        # run() is synchronous — wrap for async context
        nodes = await asyncio.to_thread(
            pipeline.run, documents=nodes_list, num_workers=builder._num_workers
        )
    return {"success": True, "indexed": len(nodes), "rules": len(rules), "collection": collection}
```

**Note on `delete_all_vectors_in_collection()`:** Use Qdrant client's `delete_payload` or recreate the collection. For a full delete+reindex, recreating the collection is cleanest — ensures no stale vectors remain. The builder already handles collection creation via `_check_qdrant_health()` + `_get_qdrant_store()`.

**Preserve:**
- `TextNode` creation in `_sigma_rule_to_rich_chunks()` — still needed for metadata attachment before pipeline (TextNode subclasses Document, accepted by pipeline.run())
- All existing metadata fields on nodes (`rule_id`, `chunk_type`, `source_file`)

### Integration Edge Cases (Murat's Risk Matrix)

| Scenario | Severity | Detection Method |
|----------|----------|------------------|
| Transformer failure mid-stream (orphaned vectors) | Medium-High | Assert `len(nodes) == len(inserted_vectors)` after pipeline |
| Zero-document ingestion (malformed YAML) | Low | Pipeline returns 0 nodes, no vector store call |
| Embedding dimension mismatch | High | Pre-existing collection + different embedder schema |
| Large document pipeline timeout (>10k nodes) | Medium | Boundary test at 10k, 50k nodes — verify memory |
| Concurrent indexing same collection | Medium-High | Two concurrent calls → total vectors = union of both sets |

**Scenario 4: Transformer failure skips remaining nodes without orphaning**

**Scenario 5: Concurrent indexing serializes writes**
```
Given two calls target the same collection concurrently
When both complete successfully
Then total vectors = union of both rule sets (no corruption or overlap)
```

## Notes from Architecture Analysis

The current `IngestionPipelineBuilder` already supports `skip_splitter=True` (line 242-250 in ingestion.py), which is exactly what we need for Sigma rules since they're pre-chunked by `SigmaChunker`.
